# Saved shell-app build inputs

The authoring build snapshot supports the repository's real `HardwareTest.ShellApps.Notes` SDK project, including its `HardwareTest.Shell.Abstractions` reference, Avalonia resources, centrally managed PackageReferences, repository build configuration, and package locks. A manifest may refer to a project outside the authoring workspace.

Capture evaluates project references and source items without running MSBuild targets or modifying original project `obj` directories. It freezes the bounded common source hierarchy, ancestor `Directory.Build.*`, `Directory.Packages.props`, NuGet configuration, `global.json`, editor configuration, existing resolved assets when present, and the full payload of every resolved NuGet package. Package folders in existing assets are honored. Restore always evaluates a disposable copy of the saved sources using the same Release configuration as publication, including SDK-inferred runtime and app-host download dependencies that package locks omit; offline requests use cache-only restore. SDK and host identities are also captured by the build service.

Preparation publishes from copied source and package payload bytes. Its NuGet configuration clears remote sources, uses the staged package folder, disables audit, and supplies fixed revision metadata so repository version targets do not consult live git state. Original resolved assets remain identity inputs; staged restore regenerates assets for staged paths. Publication rechecks all input hashes and link targets, including source tree membership, package payloads, resolved assets, and SDK identity.

The common source root must be bounded below the filesystem root. Project references must be literal relative paths. Explicit absolute or dynamic source paths, external source globs, multi-targeted graphs, custom SDKs, custom tasks, arbitrary custom targets, externally redirected intermediate/package/output directories, and imports with dynamic or absolute paths are rejected with `BUILD_SHELL_INPUTS`. SDK-discovered absolute analyzer paths inside the captured SDK/package payloads and editor configurations on the project ancestor chain are supported through the captured hierarchy. Other evaluated absolute-input errors identify the item kind and path. The repository's two version-stamping targets are supported with fixed staged revision properties. This is a deliberately bounded graph capture, not a sandbox for arbitrary MSBuild code.

`AuthoringBuildShellGraphTests` exercises the real external Notes graph through publication, confirms that original project intermediates stay unchanged, and checks invalidation after project, referenced-project, central-configuration, lock, and copied NuGet payload changes. The package mutation fixture owns a separate temporary cache; it never alters the user's shared package cache.
