# Focused authoring shell

The welcome page centers a prominent Create workspace action, a secondary Open action, and an optional recent workspace offer. A remembered workspace is offered, never opened automatically.

The header contains workspace identity, a Workspace menu, and the primary Save all, Check, and Commands actions. Commands text is vertically centered. The Workspace menu keeps Open/Create, environment preparation, catalog Undo/Redo, both specialized saves and Settings discoverable. Opening a menu commits a focused field through its existing binding, so catalog history can become unavailable when that field introduces an intervening program edit. Its existing history guard still determines availability. Keyboard commands also work from the action menus and preserve text-editing shortcuts.

A compact, full-width navigation row separates routes from actions. All seven named routes retain their indices and identities. Program selection remains in the scrolling rail beneath navigation, with New test plan, guidance, and scoped Remove program. Program Undo/Redo sits beside the inspector heading. The sequence and inspector have distinct contained surfaces, with a flexible scrolling inspector and a primary sequence viewport. Add/edit sequence actions live in a bounded menu; they do not consume the step list's height. The selected row is revealed after selection or resizing.

Hardware opens the existing program and instrument settings. Issues, Environment, and Build expose the existing finding, recovery/environment, and protected packaging views. Preview is a separate route. At client widths of at least 1280 logical pixels with normal text size (16 or below), the same preview instance can dock beside the editor. Larger text uses the separate preview route. The optional Issues drawer and collapsed Programs rail retain their saved preferences.

The command palette separates the search header from scrolling results. Command titles and shortcuts occupy distinct columns. A bottom viewport inset separates results from the action footer; the last result remains reachable. The footer explains unavailable commands and retains Run and Cancel. Light, Dark, and System preferences use the same layout with theme-specific surface colors.

Operation progress/cancellation, status, unsaved state, validation scope, error feedback, and Save all results retain their existing guards and live announcements. Validation scope sits in the status footer so navigation remains directly beneath the header. Navigating back restores the focused editor control, selection, and scroll position. Protection dialogs retain Cancel as their safe default.

`ResponsiveShellTests` and `ResponsiveActionLabelTests` verify actual client containment at 960×600 and 1280×800, including 150% render scaling, larger text, long labels, and operations in progress. `FocusedShellDesignTests` covers centered welcome creation, Commands alignment, search/result separation, the bottom viewport gap and a 16-pixel trailing content inset, reaching the last command, unavailable actions, and Escape. The headless app includes the production authoring styles so these checks exercise the same geometry as the native app. `FocusedShellInteractionTests` uses pointer input on the visible Workspace and Add/edit triggers, selects a recipe, scrolls to lower actions, and dispatches a displayed command. It verifies rendered palette titles/shortcuts through successive filters, no results and recovery, menu/palette containment at font size 20, and a remembered welcome at font sizes 20 and 24. Popup content inherits the owner’s text size. Existing routing, history, lifecycle, guidance, recording, and preview tests continue to exercise the original operations.

Native verification uses a Release `linux-x64` publish with its declared runtime assets, not a headless rendering. Welcome, editor, and command palette screenshots cover normal and minimum window sizes, with an additional Dark-theme capture. Screenshot artifacts and publish/test logs are attached to the implementation review.

The unreachable former rail automation identity `Open last workspace` was removed. The reachable recent offer retains `Open last workspace from welcome` on the welcome page. The welcome viewport scrolls when larger text or the recent offer exceeds its available height.
