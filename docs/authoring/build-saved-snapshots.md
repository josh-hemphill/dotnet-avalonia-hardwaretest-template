# Build saved snapshots

`WorkspacePacker.Pack` is the shared CLI and GUI entry point. It captures the saved manifest and source bytes through `AuthoringBuildService.CaptureSaved`, prepares isolated artifacts with `Prepare`, and publishes them with `Publish`. `Execute` composes preparation and publication. A disposable `AuthoringPreparedBuild` owns its staging tree; it exposes immutable results, not editable source buffers or staging paths.

The request owns saved bytes and records file hashes, canonical dependency targets, and relevant environment identities. Mutable caller manifests and editor drafts are not build inputs. Current supported authoring sources take precedence; compiled plans are imported only when their source is absent. Corrupt, future, unknown source fields and incomplete deployment values fail explicitly. Existing compiled artifacts must still match the source's saved baseline, including when compilation is pending. External compiled edits require explicit reconciliation. Compilation updates baselines only in staging, never in original source documents or compiled files.

Staging contains copied plans, authoring sources, plugin packages and selected OpenTAP homes. Saved sources are compiled there, checked with strict contract validation, and compared against the staged selected homes. Existing template inclusion rules are retained; excluded plans are not packaged. Source maps retain supported setup, metric and repeat node identities, and distinguish generated steps from opaque imported steps. Opaque steps do not claim a reliable authoring-node mapping.

The separate versioned `authoring-build-receipt.json` preserves existing `ship-manifest.json` consumers. It records included/excluded plans, saved program and workspace revisions, source hashes, captured dependencies and environment identities, required checks and checker provenance, source maps, and hashes of every produced artifact plus the ship manifest. The receipt itself is checked against its prepared hash at publication; it is not recursively included in its own output-hash list. An injected checker is identified explicitly and does not imply external TUI coverage.

Publication verifies original input/tree membership, environment identity, resolved link targets and containment, the exact prepared artifact set, artifact hashes and receipt bytes. It checks cancellation before and during publication, and rechecks input identity at the receipt boundary and after output moves. Receipt-last output replacement retains preimages and rolls back normal failures or cancellation. If restoration itself fails, the exception identifies retained recovery preimages. This protects failed operations; it is not a crash-safe filesystem-wide transaction. Consumers using receipts must verify their recorded output hashes.

GUI eligibility permits complete saved sources awaiting compilation. Known incomplete deployment values, source conflicts, read-only data, deleted known sources, or unsaved edits block packaging. Eligibility is permission to attempt a build, not evidence of a successful compile or deployment. A build does not mark original pending compiled artifacts current.

[Shell input capture](build-shell-inputs.md) describes the supported evaluated SDK/project/NuGet graph and actionable unsupported-input errors. Runtime logs and package-cache metadata are excluded from selected-home identity; package payloads and runtime configuration remain inputs.

`AuthoringExternalTuiProcessTests` uses an actually installed external OpenTAP/TUI home (optionally selected with `AUTHORING_EXTERNAL_TUI_HOME`), copies it, installs actual authoring Basic/Mixins payloads, compiles saved authoring source with mock instruments, and observes the plan sentinel in a bounded real PTY. It never selects Run or executes hardware. Missing external prerequisites are reported as unavailable via an explicit skipped test. This establishes external process plan-load integration, not an external save roundtrip or a replacement for all production compatibility checks.
