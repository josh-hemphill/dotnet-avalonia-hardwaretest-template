# Package 17 compiled recording evidence

Generated by `BoardPreviewTests.Compiled_recording_mean_and_filter_chain_match_values_units_verdict_and_execution_scopes` during the Release linux-x64 scoped test run. These are generated execution fixtures, not evidence of completed native desktop review.

Each `pass` / `fail` folder is a standalone authoring workspace containing the actual compiled `board.TapPlan`, its program sidecar, the matching original authoring source under `authoring-drafts`, and an actual host `run.json` recording. Open a folder as a workspace, then use Import recording to select that folder's `run.json`.

The test executes the compiled draft through the in-process `OpenTapSession` with `MockDmmInstrument`: two repeat iterations, three acquired samples per iteration on a 5 ms grid, two cascaded `[0.5,0.5]/[1]` filters, and a mean criterion in volts. The pass threshold is 0; the fail threshold is 100. This is simulated test execution, not a live station or physical hardware run.

Producer GUIDs, step-run GUIDs, loop paths and iteration indexes in these recordings originate from the actual host callbacks and survive JSON serialization. The test compares recording-derived preview means with the actual compiled scalar values, units and verdicts. The board's derived values are computed offline from those source execution samples and are labeled as such; those displayed calculations are not new hardware execution or invented derived step-run identities. Legacy fixtures without these optional fields remain explicitly unknown.
